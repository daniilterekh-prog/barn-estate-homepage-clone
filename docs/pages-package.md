# Пакет публикации GitHub Pages

Цель: сохранять рабочие страницы и скачивания без изменения байтов, исключить служебные проверки из deploy и ограничить накопление временных пакетов. Репозитории, история, исходники, отчёты и ZIP из Git не удаляются.

Рассмотрены три способа: публикация всего корня (прежний режим, включает проверки); граф только найденных зависимостей (может пропустить динамические изображения и внешних потребителей URL); консервативное исключение служебных путей. Выбран третий способ: сохраняются все runtime-ассеты, включая не упомянутые статически, блоки/paste.html, ZIP, handoff и публичные инструкции.

## Реализация и проверка

1. `scripts/build-pages-package.py` читает только tracked-файлы Git. В новый каталог копируются без преобразований все файлы, кроме каталогов проверок/scripts/tools/tests, корневых docs, скрытых служебных файлов и Node/Python тестовых/служебных скриптов. Каталоги assets/source и `_nuxt` сохраняются. Существующий выходной каталог запрещён. Отчёт о путях, размере и SHA-256 записывается вне сайта.
2. `tests/test_pages_delivery.py` проверяет реальные файлы и границы очистки; отдельно проверяет сохранение текущего пакета, последнего успешного и всех активных запусков.
3. `.github/workflows/pages.yml`: тесты → сборка → загрузка пакета со сроком один день → публикация → очистка старых пакетов. Права actions:write выдаются только заданию очистки. Все используемые Actions закреплены SHA.
4. Очистка затрагивает только artifacts `github-pages` завершённых запусков. Текущий пакет и последний предыдущий успешный сохраняются; незавершённые запуски защищены. Список пагинируется. Перед каждым удалением повторно проверяется статус запуска. Другие имена artifacts и workflow runs не удаляются.
5. До переключения Pages проверить 13 текущих страниц и библиотеки/скачивания: файлы пакета совпадают по SHA, браузерные запросы к локальным ресурсам не добавляют ошибок относительно полной рабочей копии. После публикации проверить успешный Actions run и ключевые публичные URL.

Отдельная очередь публикаций `pages` предотвращает одновременные deploy; публикация не отменяется посередине. Служебные изменения и корневые README/оглавления не создают новых выпусков. Изменения публичных инструкций блоков продолжают публиковаться.

## Запуск

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build-pages-package.py --output /absolute/new/site --report /absolute/package-report.json
# Сначала только план очистки: GITHUB_TOKEN, GITHUB_REPOSITORY и GITHUB_RUN_ID задаются окружением.
python3 scripts/retain-pages-artifacts.py --dry-run
```

Оригиналы остаются в Git. Уменьшение каждого пакета ограничено: после удаления скриншотов основную массу составляют рабочие материалы. Основная экономия хранения — ограничение количества завершённых пакетов.

## Откат

В Settings → Pages вернуть Source «Deploy from a branch», branch `master`, folder `/`, затем отключить workflow `Publish Pages package`. Старый способ снова публикует прежний полный корень. Контент страниц и скачивания не преобразуются новой сборкой, поэтому для возврата не требуется восстановление исходников.

Источники: [официальные custom workflows Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [upload-pages-artifact v4](https://github.com/actions/upload-pages-artifact/tree/v4), [deploy-pages v4](https://github.com/actions/deploy-pages/tree/v4). Дополнительные зависимости для сборки/очистки не устанавливаются: используется стандартная библиотека Python 3.
