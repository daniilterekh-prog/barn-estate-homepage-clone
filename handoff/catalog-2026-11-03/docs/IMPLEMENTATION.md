# Устройство и перенос

## Сборка

Статические HTML/CSS/JavaScript, без npm-зависимостей и шага сборки. Главный файл — `site/index.html`. При переносе сохранить порядок `<link>` / `<script defer>` из него: исходный кит → адаптеры каталога. Подключение скриптов повторно на странице не допускается: модули создают общие singleton-состояния и диалоги.

| Файл / папка внутри site | Роль |
| --- | --- |
| `index.html` | Одна шапка, навигация, панель фильтров, шаблоны карточек/карты/меню, футер |
| `direction-profiles.js` | Департаменты, доступные сделки, параметры фильтров, подписи |
| `filter-adapter.js` | Настройка общей формы под департамент |
| `kit/filters-modal/` | Единое состояние фильтров, черновик формы, применение/отмена |
| `kit/quick-filter-dropdowns/` | Общий dropdown, синхронизация выбора и подборок |
| `listing.js` | Загрузка данных, поиск/фильтрация/сортировка, карточки, URL, избранное и меню |
| `catalog-active-filters.js` | Выбранные условия и удаление отдельных фильтров |
| `catalog-map.js` | Полноэкранная карта и список из общего снимка выдачи |
| `header-navigation.js` | Наведение, клавиатура и касание у списков направлений |
| `catalog-kit-v1.js` | Адаптер общего кита, компактная шапка и мобильный порядок поиска |
| `listing.css`, `catalog-kit-v1.css`, `catalog-filters.css`, `catalog-map.css` | Локальная композиция и уточнения дизайна |
| `kit/_shared/` | Базовые стили, шрифты и исходные компоненты |
| `kit-v1/` | Кит главной: шапка/контакты, футер, квиз, типографика, отступы, кнопки |
| `assets/`, `reference-shell/`, `map-view/` | Изображения и исходники оболочки; лицензия карты |
| `objects.json` | Демонстрационные записи каталога |
| `data-sources.json`, `kit-sources.json`, `kit-v1/sources.json` | Происхождение данных, кита и ассетов |

В `kit/` и `reference-shell/` сохранены исходные фрагменты. Активная согласованная сборка — именно `index.html`; отдельные старые фрагменты не заменяют её.

## Перенос

1. Запустить `site/` и сравнить с контрольными снимками.
2. Перенести разметку и локальные адаптеры в шаблон сайта, сохранив class, `data-*`, `id`, `aria-*` и порядок подключения. Исходные `data-v-*` участвуют в CSS сохранённой сборки; удалять их можно только вместе с осмысленным переносом соответствующих селекторов.
3. Использовать одну шапку и один футер. Если CMS уже выводит их, встроить согласованные фильтры/выдачу в существующую оболочку и сверить меню, мобильный хедер и отступы.
4. Сохранить относительные пути либо перебазировать их одновременно в HTML, CSS `url(...)`, JS `new URL(...)` и поле `image` объектов. Загрузка `objects.json` идёт относительно URL страницы.
5. Подключить реальные данные и обработчик `barn:lead` по INTEGRATION.md.
6. Повторить приёмку из BEHAVIOR.md. Превью содержит `noindex,nofollow`; robots/canonical для рабочего сайта настроить в его шаблоне при внедрении.

Все URL внешних страниц и объектов сохранены. Если меняется маршрутизация основного сайта, обновить их централизованно, включая JSON-навигацию, футер и данные объектов. Все параметры URL нужно сохранять при переходах/перезагрузке.
