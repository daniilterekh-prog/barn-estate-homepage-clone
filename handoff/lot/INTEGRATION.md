# Подключение

1. Скопировать папки `html/`, `css/`, `js/`, `assets/` с сохранением структуры. `html/index.html` — полная самостоятельная страница, `index.html` в корне — переход на неё.
2. Сохранить порядок `<link>` и `<script defer>` из полной страницы. В `data/resources.json` тот же порядок и контрольные суммы. CSS/JS не зависят от соседних страниц сайта. Иконки и локальные шрифты включены; новые npm-пакеты не нужны.
3. На body оставить `class="lot-page" data-hero-variant="3"`, `#main`, IDs блоков/диалогов/форм и встроенный JSON навигации. `lot-page.js` содержит рендерер и обработчики. Он заново создаёт `#main` при инициализации.
4. Для реального объекта передать разрешённую публичную модель **до** `js/lot-data.js` и `js/lot-page.js`:

```html
<script>
window.BARNES_LOT_DATA = /* безопасно сериализованный публичный объект */;
</script>
```

`js/lot-data.js` — только пример601669; если данные уже заданы, он их не заменяет. При серверной вставке JSON экранировать `<`/закрывающий script, либо загружать JSON отдельно. Не вставлять raw CRM HTML. Для обновления после инициализации: `window.renderBarnesLot(publicLot)`.

Пути изображений в `data/lot-601669.json` рассчитаны относительно `html/index.html`. При иной структуре сервера переназначить URL ресурсов. В JS сохранены лишь два заменённых префикса локальных ресурсов: `../assets/brand/` и `../assets/icons/lucide/`; карта преобразований есть в `data/file-map.json`.

## Фрагменты

`html/00-head-resources.html` — только содержимое head; `01-header.html` — skip-link, хедер/меню и компактная навигация. Далее по одному section на файл. Последний файл содержит футер, плавающего эксперта, диалоги и JSON навигации. `data/fragments.json` даёт точный список/порядок.

Если разработчик рендерит блоки сервером, обернуть секции в `main#main`, учесть автоматическую перерисовку `lot-page.js` и перенести необходимые обработчики в контроллер CMS либо использовать штатную схему «публичные данные → рендерер». Фрагменты — разметка для интеграции, не отдельные запускаемые страницы.

## Действия

- Стрелки херо: смена собственного фото, клавиатура и свайп. Счётчик скрыт визуально, остаётся live-объявлением для скринридера. Одна фотография — без стрелок.
- План: отдельный файл, диалог/увеличение/Escape/возврат фокуса.
- Описание: полное поле в DOM; свернутый текст и кнопка не выше фото, пересчёт после шрифта/изображения/resize; короткий текст без кнопки.
- Формы: валидация, имя/телефон/согласие/канал/комментарий, контекст ID; после submit только подготовка mailto/телефона. Реального POST/CRM нет. При подключении транспорта предусмотреть loading/error/success и реальный ответ сервера.
- Рассылка: проверка email и подготовка запроса. Для подписки нужен сервис и его согласия; не показывать успех до подтверждения сервера.
- Похожие: реальные публичные ссылки, избранное в памяти страницы, обращение с ID выбранной карточки. Нужна серверная выборка вместо статических примеров.
- Карта: внешний Yandex iframe; может содержать интерфейс/рекламу провайдера. Для продакшен-карты выбрать согласованный провайдер/способ подключения отдельно.

Руслан в CTA/плавающем блоке — согласованный агентский компонент, а не назначение ответственным брокером квартиры. В примере используется общий публичный контакт; связь с ответственным сотрудником подключается отдельно.
