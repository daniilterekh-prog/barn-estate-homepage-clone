# Подключение

## Самостоятельная страница

Полный документ — `html/index.html`. Корневой `index.html` перенаправляет на него. Запускать через HTTP: `python3 -m http.server 8080` из папки пакета. Сохранить взаимное расположение `html/`, `css/`, `js/`, `assets/` и `data/`.

Все CSS и JS подключены в исходном порядке; встроенные блоки вынесены в отдельные файлы без изменения порядка. Не сортировать подключения по алфавиту. Параметры `?v=` можно оставить. Неиспользуемые preload старой Nuxt-сборки удалены; Nuxt, Vue, npm и серверный рендер для этой версии не нужны. Имена owner-sale сохранены для совместимости селекторов существующего UI-кита.

## Перенос в CMS

`head.fragment.html` и `body.fragment.html` — части документа, а не самостоятельные страницы. Перенести содержимое head в head шаблона, body — внутрь body, атрибуты body взять из `data/body-attributes.json`. Не добавлять фрагменты повторно в полную страницу.

Пути фрагментов рассчитаны на итоговый документ в `html/`. При ином размещении переписать ресурсные пути и строковые пути в JS/CSS вместе. Рекомендуется сохранить отдельную папку пакета и подключать ресурсы из неё. В HTML нет base: он изменит якоря и разрешение путей и требует отдельной проверки. Не подключать одновременно второй хедер, футер или контроллер формы.

Часть содержимого создаётся нативными контроллерами: вкладки преимуществ, карточки пяти этапов, навигация, плавающий эксперт и окно формы. Поэтому для полного результата нужны все JS из полного документа. Подключать их с исходными defer/атрибутами data-*, не добавлять async. Классы owner-sale-reference-ui и атрибуты кита сохраняются.

## Структура и действия

1. Первый экран: консультация.
2. Четыре услуги: городская, загородная, коммерческая продажа и аренда.
3. Панорама преимуществ: четыре вкладки, переключение кликом и клавишами.
4. Пять этапов: стрелки, Left/Right/Home/End и свайп на телефоне.
5. Стратегия: консультация. Далее — полный футер.

Якоря: `#property-types`, `#why-barnes`, `#services`, `#request`. Основные CTA открывают одно окно эксперта. Внешние переходы сохранены как в согласованном превью; часть общего меню указывает на frontend-домен `front.barnes.vsavr.ru`, который может требовать авторизацию. Адреса меню для production нужно сопоставить с маршрутами CMS. Сам пакет их не заменяет.

Согласованные временные адреса карточек:

- Городская, загородная и коммерческая продажа → `https://daniilterekh-prog.github.io/barn-estate-homepage-clone/prodazha_sobstvennikam/`.
- Аренда → `https://daniilterekh-prog.github.io/barn-estate-homepage-clone/arenda_sobstvennikam/`.

Перед production заменить их на окончательные адреса, сохранив смысл карточек. Структурированный список — `data/service-links.json`.

## Заявки

Обработчик в `js/shared-expert-dialog.js` поддерживает имя, телефон, согласие и каналы Telegram/WhatsApp/MAX/Звонок. Проверяет поля и выводит честный статус превью. Отправки, CRM, почтового API и серверного обработчика в пакете нет; кнопка не означает доставку заявки.

Разработчику подключить приём заявки на сервере, серверную валидацию, обработку согласия, ошибки/повторную отправку и подтверждение только после успешной доставки. Не помещать секреты CRM в браузерный JS. Сохранить закрытие по Escape, удержание фокуса в диалоге и возврат фокуса к CTA. Ссылки мессенджеров из общего меню остаются обычными пользовательскими переходами.

## Публикация

В превью сохранён `noindex,nofollow`. Для production отдельно настроить canonical/robots/sitemap, метаданные и аналитику по правилам основного сайта. Эта передача не устанавливает код на боевой домен. Семь редакционных сцен сгенерированы; это иллюстрации, не конкретные лоты. Портрет Руслана, логотипы и фотографии конкретных ЖК сохранены из исходника.
