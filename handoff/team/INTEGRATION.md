# Подключение

Готовая страница — `html/index.html`. Это статический HTML с обычным JavaScript; Nuxt/Vue/React не требуются.

## Структура

```text
handoff/team/
  html/index.html                полная страница
  html/01-header.html            хедер, данные меню и9подменю
  html/02-team-directory.html    крошки, H1, поиск, фильтры,27карточек
  html/03-expert-question.html   компактный CTA
  html/04-footer.html            футер
  css/team.css                  композиция, каталог, карточки, поиск
  css/header/                   исходные стили хедера и интеграция
  css/form/                     исходные стили формы главной
  css/shell/                    футер и хлебные крошки
  js/team.js                    поиск, фильтры, выравнивание имён, CTA
  js/header/                    меню, контакты, фокус, закрепление
  js/form/                      форма главной
  assets/team/                  портреты команды, исходные SVG/шрифты
  assets/header/                логотип, мессенджеры, фото меню, шрифты/лицензия
  assets/form/                  десктопный и мобильный портрет формы
  data/                         состав команды и происхождение компонентов
```

Фрагменты `01–04` предназначены для встраивания, а не отдельного открытия в браузере. Их порядок, CSS, JS и классы оболочки бери из полного `index.html`. Фрагмент каталога включает крошки; хедер включает оба JSON-блока конфигурации. SVG и `data-v-*` сохранены: их используют селекторы исходного кита.

## Порядок подключения

CSS: футер → стили хедера → белая тема → выпадающие подменю → team.css → крошки → форма главной. Точный порядок и URL уже записаны в `<head>`.

JS с `defer`: форма главной → header-runtime → header-focus → header-navigation → team.js. Сначала должна появиться разметка, затем контроллеры. Не подключай параллельно прежний хедер, старые `01-site-header.css`/`site-menu.css`, старые обработчики бургера или вторую версию формы.

Классы `<body>` — `barnes-home-typography team-page`. Хедер имеет `.barnes-block.barnes-home-typography` и `data-barn-block="01-header"`; футер — `data-barn-block="15-footer"`. Они нужны для стилей, JSON и управления фокусом. `html { scrollbar-gutter: stable }` предотвращает скачок при меню/форме.

## Данные и контакты

`data/team.json` фиксирует состав и происхождение, но не загружается в браузере: все27карточек уже находятся в HTML. При изменении состава синхронизируй HTML-карточки, `data-person-id`, `data-groups`, поисковые данные и JSON. Руководители остаются также в профильном направлении.

Поиск/фильтры работают локально; серверный API не нужен. Кнопка `[data-home-form-open]` вызывает `window.__barnesOwnerForm.open({trigger})`. Этот же API используется кнопкой заявки закреплённого хедера. При встраивании оставь одну копию формы и её стилей.

Форма не отправляет данные. Серверный endpoint, CRM, политика хранения и сценарий подтверждения доставки должны быть подключены отдельно. Не заменяй текущий статус фиктивным сообщением об отправке.

Счётчик избранного читает существующий ключ `barnes-catalog-favorites` из localStorage. Сам каталог команды его не меняет. Для общего счётчика страницы должны работать на одном origin. Переходы главной/избранного в пакете сделаны абсолютными на публичное превью; перед установкой замени их на адреса своего домена. Остальные контакты/ссылки сохранены из источника.

На production отдельно настрой canonical/метаданные и robots: в переданном превью оставлен `noindex,nofollow`.

## Пересборка и проверка

`tools/build.py` запускается из Git-checkout с каноническими исходниками. Использует только стандартную библиотеку Python и Git; `--source /путь/к/team` задаёт папку источника. Он перебазирует URL и пишет `SOURCE.json`, не меняя рабочую страницу.

`tools/verify.cjs` использует Playwright из установленного Toolkit или из переменной `PLAYWRIGHT_MODULE`. `HANDOFF_URL` — URL `html/index.html`, `TEAM_URL` — URL канонической страницы для сравнения. Тест создаёт замеры и `VERIFICATION.json`. Получателю не нужно запускать эти инструменты для просмотра или установки.
