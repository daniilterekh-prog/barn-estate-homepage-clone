# Подключение

## Полная страница

Разместить папку целиком и открыть `html/index.html` через HTTP. Это самодостаточная страница без сборщика. У CSS, JS и изображений относительные пути; CSS `url('../assets/...')` разрешаются от `css/`. Ключи API, cookies и доступы не требуются и в пакет не входят.

CSS и `defer`-скрипты подключены в правильном порядке в `<head>` полной страницы. Порядок нельзя менять: `page.css` задаёт основу, последующие файлы уточняют компоненты; `js/vendor/splide.js` загружается до `news.js` и `gallery.js`. Сохранить классы body `barnes-header-template barnes-media-header barnes-zhk-footer`.

## Перенос в существующий шаблон

1. Взять подключения из `html/00-head-resources.html`; метаданные, title и description заменить данными конкретного ЖК. `noindex,nofollow` сохранён для превью; решение об индексации принимается при реальном запуске.
2. Вставить `01-header.html`, затем `<main id="main">`, фрагменты `02-project.html`–`15-expert.html` в этом порядке, закрыть `main` и вставить `16-footer-dialogs.html`.
3. Все фрагменты рассчитаны на тот же уровень вложенности, что `html/index.html`. При переносе в другой маршрут скорректировать `../css`, `../js`, `../assets` и `data-image`; не использовать глобальный `<base>`, который изменит якоря.
4. Не дублировать хедер/футер или контроллеры, если их предоставляет общий шаблон. При замене соблюдать те же ID/классы и DOM-контракт либо адаптировать соответствующий локальный скрипт. Каждая секция и каждый ID должны встречаться один раз.
5. Внутренние ID — `project`, `passport`, `apartments`, `architecture`, `gallery`, `territory`, `location`, `purchase`, `developer`, `documents`, `faq`, `similar`, `newsletter`, `expert`. При скрытии секции удалить и ведущие к ней якоря.

`00-head-resources.html` содержит метаданные и подключения, без обёртки `<head>`. Остальные фрагменты не являются отдельными страницами; для проверки использовать полную страницу.

## Контроллеры

| Файл | Что делает |
| --- | --- |
| `media-header.js`, `header.js` | Меню, способы связи и переход прозрачного хедера в белый после прокрутки |
| `page.js` | Контактный диалог, увеличение плана, заглушки отправки двух форм; старый обработчик data-room не задействован без вкладок |
| `footer.js` | Мобильные группы футера |
| `floating-expert.js` | Плавающая карточка эксперта; скрывается у финального CTA, футера и открытого диалога |
| `related-projects.js` | Локальное поведение карточек похожих проектов |
| `news.js`, `gallery.js` | Карусели, свайп, стрелки; галерея открывает просмотр изображения |
| `optional-characteristics.js` | Валидирует три необязательных поля и добавляет ячейки в общую сетку |
| `description.js` | «Читать далее» при тексте длиннее фотографии, на телефоне — компактный предпросмотр |
| `infrastructure.js` | Первые два абзаца инфраструктуры, остальные под «Читать далее» |

Для клиентского роутера/SPA существующие IIFE и обработчики запускаются после появления DOM страницы. Они не предоставляют mount/unmount API; разработчик должен обеспечить одиночную инициализацию и освобождение observer/listeners при уходе со страницы. В обычном HTML это не требуется.

## Диалоги и формы

`[data-contact]` открывает `#contact-dialog`, тема берётся из атрибута. Основная кнопка подборки использует `data-contact="Индивидуальная подборка квартир"`. Hero, карточка эксперта и остальные CTA используют тот же диалог. Картинки открываются из `data-image`, путь должен быть доступен браузеру относительно документа.

Сейчас оба `submit`-обработчика в `js/page.js` вызывают `preventDefault()` и показывают честное сообщение о том, что заявка не отправлена. Подключить реальный backend/CRM, серверную валидацию и фактические статусы отправки. Не оставлять одновременно заглушку и реальный обработчик. Не помещать токены Intrum в клиентский код. Проверить согласие, ошибки, клавиатуру и повторную отправку после подключения.

## Внешние сервисы и источники

Яндекс iframe уже встроен и загружается лениво; координаты задаются параметрами `ll` и `pt` в долготе/широте. Собственного API-ключа карта не использует. Внешние новости, документы и мессенджеры остаются переходами по исходным URL. Десять изображений новостей сохранены в `assets/news/` и больше не требуют доступа к папке главной.

Подключение на боевом домене не выполнялось. Реальный транспорт формы, CRM-поля, разрешение публикации, связь ЖК с лотами и внешние ссылки нужно проверять в рабочей интеграции.
