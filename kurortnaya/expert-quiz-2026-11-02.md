# Микро-квиз обращения к эксперту · 02.11.2026

Запрос: добавить микро-квиз в форму, открываемую плавающим экспертом.

Основа — утверждённая главная `exact-2026-10-21/blocks/17-quiz/`: три вопроса, затем контакты; постоянная высота окна, возможность пропустить подбор, возврат к ответам. Принято исполнителем для Курортной: цель (отдых/жизнь, инвестиции, совмещение, консультация), курорт (Сочи, Анапа, Алтай, Архыз, Шерегеш, Санкт-Петербург, «Пока выбираю»), свободный бюджет и валюта ₽/$/€ либо «Пока не определился». Это адаптация сценария, не новые данные каталога.

Подходы: целиком переносить большой runtime главной вместе с общими блоками не нужно; отдельная новая форма дублировала бы существующие контакты/портрет. Выбран небольшой общий контроллер поверх текущего попапа. Квиз запускается только экспертом (или явным data-expert-quiz); хедер/футер и CTA продолжают открывать прямую форму. Денис и существующие изображения сохраняются.

1. `js/expert-quiz.js`: шаги/ответы, пропуск, возврат, итог, hidden quizAnswers, доступная валидация контактов.
2. `css/expert-quiz.css`: роли главной, бордо/белый, фиксированное окно и прокрутка тела; без новых изображений/пакетов.
3. `js/ui-kit-runtime.js`: запуск по эксперту и сброс режима при прямой форме; настоящее событие `barn:lead` с ответами. До подключения обработчика данные не отправляются, ложного успеха нет.
4. `blocks/_shared/runtime.js`: тот же контроллер и FormData для onSubmit; переносимый request-modal поддерживает оба режима.
5. Проверка: 320–3840px, выбор/назад/пропуск, сохранность ответов, валидация/согласие, keyboard/focus/Escape, короткий viewport, отсутствие реальных отправок и ложного успеха, обычная форма и автономный эксперт.
6. Обновление страницы, частных исходников, кита и канонических блоков; commit + push после проверок.
